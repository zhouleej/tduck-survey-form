# 问卷短信调研部署与验收

适用分支：前后端 `codex/survey-sms-workflow`。实施日期：2026-10-26。范围和约束见[开发计划](问卷短信调研开发计划.md)，协议实测见[开放接口联调记录](云信开放接口联调记录.md)。本次开发未发送真实短信，文本模板申请只经过模拟网关验证。

## 上线顺序

1. 备份目标数据库，确认应用实际连接的库。先停止旧实例或保持调研开关关闭。
2. 在同一目标库按顺序执行 `doc/migrations/20261026_01_survey_recipients.sql` 至 `20261026_06_survey_upstream.sql` 六个增量脚本。脚本只新增调研表及字段，不重建原有问卷表；数据库账号需要 CREATE、ALTER、PREPARE 权限。迁移版本由部署系统记录，运行中的应用不会自动执行脚本。
3. 后端 Java 8 构建：`mvn -pl tduck-api -am package -DskipTests`。部署生成的 `tduck-api/target/tduck-api.jar`。部署前端 `npm run build` 生成的 `dist`，前后端须配套更新。
4. 为前端配置可公网访问的 HTTPS 域名和路由回退，包括 `/i/邀请标识` 及原 `/s/问卷编号`。管理端“系统配置→短信配置”填写“邀请公网地址”；不要使用 localhost。网关所在服务器时间应同步，业务发送时间按北京时间计算。
5. 调研、申请模板、审核查询、回执查询、上行查询分别启用。默认全部关闭；编辑和保存本地名单、模板无需开启发送。配置修改可能暂停旧配置创建的待发批次，核对后再继续。

本地开发库已执行六个脚本并记录迁移；原问卷、答卷未被迁移脚本修改。本地保持功能开关关闭，未创建生产邀请批次。

## 云信配置

继续使用已有云信用户名、企业 ID、接入号、扩展码配置，保留前导零。发送固定使用已配置的开放发送路径，默认 `/prod-api/tripartite/task/v2/send`。不使用云信网页内部接口或网页登录凭据。

本账户 2026-10-26 的正式只读联调结果可通过管理端“应用已验证查询配置”填入：

| 配置 | 实测值 |
|---|---|
| 回执结构版本 | `JX_20261026` |
| 查询开始时间字段 | `beginTime` |
| 查询时间格式 | `yyyy-MM-dd HH:mm:ss` |
| 查询业务成功码 | `200` |
| 审核、上行业务成功码 | `200` |
| 已确认发送失败码 | `1001` |

应用预设不会自动开启查询或发送。该账户的 `startTime` 会被网关忽略；回执无总数且越界页重复末页，实测版本显式处理重复末页。其他账户需重新核对，不能直接沿用。陌生状态保留未知；送达失败码不得凭经验填写。

审核返回的运营商字段可能缺失，页面会显示覆盖范围未知，需要操作者确认。绑定模板必须填写与云信完全一致的正文和变量规则；现有五段链接可使用自动分段映射。申请新模板前先用模拟环境验证，再由管理员开启申请能力；申请结果未知时先在云信核实和绑定 ID，避免重复申请。

## 使用与状态处理

- 在问卷“短信调研”中导入名单：Excel 最大 2MB、1万行，先预检再确认。手机号在问卷内唯一，可选择跳过重复或更新提供的属性。
- 默认匿名；首个批次创建后模式锁定。跟踪模式填写前有提示，可查看联系人进度和关联答卷；匿名不提供逐人答卷或未完成人员清单。
- 选择模板、对象和立即/预约时间，先预览，再确认。确认请求冻结预览的对象 ID；名单资料、模板、审核或配置变化需要重新预览。后续新增联系人不会被悄悄加入该批次。
- 每批最多1万人，每次网关请求最多100人，默认北京时间8点至20点发送。数据库租约控制多实例任务，逐号变量、发送尝试和模板正文快照持久化。
- 提交、发送、送达、参与分别展示。供应商任务号可能被复用，不能当作本地批次号。回执按身份、号码和时间等证据匹配，歧义进入待确认；没有匹配证据时不覆盖最近一条记录。
- 发送超时或进程中断进入“受理未知”，不会自动重发。经人工核实后可登记任务号并补查，或有依据地确认未受理；处理会留审计记录。暂停、取消只影响本地未提交部分，已提交短信不能撤回。
- 回执按约1/5/15/60分钟退避查询，72小时未确认显示超时，不能视为送达失败。管理员可在供应商保留期内人工补查；查询失败保留游标和错误，不跳过失败页。
- 跟踪模式手动催答会排除已完成、拒收、停用、处理中、受理未知及24小时内已发送对象，执行前再次检查；匿名仅支持再次邀请。没有自动催答任务。
- 管理员在回复收件箱同步、人工分配和处理上行。普通问卷用户只能看已分配到其有权限问卷的回复。退订处理产生本地账户级拒收，发送前复查；不会调用未提供的云信黑名单或回复发送接口。
- 统计页区分对象人数、发送尝试、实际分段数和答卷数；只有正式回执返回的 `splitSize` 才计入实际分段，预览估算不作为计费依据。可导出明细、回复和跟踪模式未完成名单。

## 验证记录

本次执行结果：34项单元测试、17项独立数据库集成测试全部通过，均无跳过；前端 ESLint 和生产构建通过。集成测试使用单独创建的 `tduck_survey_test_*` 数据库及本地模拟网关，未向云信发送短信。

覆盖：100+1分片、逐号变量、超时未知不重发、幂等及并发重复请求、租约竞争、答卷事务回滚、匿名隔离、万条导入预览、名单预览冻结和资料变更、重复及歧义回执、多页查询失败重试与末页重复、迟到回执、提醒执行前复查、回复权限、拒收、导出文件与公式转义。页面走查覆盖名单预检后取消、模板变量映射、禁用状态、回复和邀请统计；未进行真实短信发送端到端验收。

可复现单元测试（PowerShell 中请整体引用 `-D` 参数）：

```powershell
mvn -pl tduck-form -am test '-Dtest=YunxinSmsServiceImplTest,Survey*Test,FormSmsInviteServiceTest' '-Dsurefire.failIfNoSpecifiedTests=false'
```

数据库测试需先创建隔离 MySQL 库，配置 `SURVEY_TEST_JDBC_URL`、`SURVEY_TEST_DB_USER`、`SURVEY_TEST_DB_PASSWORD`，再执行：

```powershell
mvn -pl tduck-api -am test '-Dtest=SurveyWorkflowDatabaseTest' '-Dsurefire.failIfNoSpecifiedTests=false'
```

测试会在指定库创建并清理业务表，严禁指向生产库。测试类只接受含 `tduck_survey_test_` 的库地址，且未提供环境变量时跳过；验收必须检查报告中实际执行数和跳过数。

## 小范围上线验收

配置公网域名、绑定已审核模板并核对覆盖范围后，由业务方在允许时段使用少量明确同意的号码，完成导入→预览→发送→回执→访问→提交→手动催答→导出。分别验证匿名和跟踪问卷；开启前先确认费用、模板、对象与名单数。万级容量通过测试验证，不发送万条验收短信。

回滚时先关闭调研发送开关、暂停待发批次，再回退配套应用。保留调研表和发送历史，避免丢失未知受理记录导致重复发送；不要删除表或清空发送尝试。已提交云信的短信不会随应用回滚而撤销。
